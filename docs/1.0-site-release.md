# oscine.app — 1.0 release design

Status: agreed 2026-08-29. This is the working spec for getting the site over the line alongside Oscine 1.0.0. Decisions here were made in conversation; change them here first, then in code.

Facts about the app repo as of 2026-08-29: `thoughtreactordm/oscine` is **public**, Issues are enabled, the license is MIT (LICENSE and `package.json` already say so; README/license refresh is PR #22, pending), and the repo description reads *"A well-designed and robust player for music and podcast nerds."* Releases are cut by `.github/workflows/ci.yml` on a version bump to `main`.

## 1. What the site is for

Oscine is one local music player among many. It does not have a unique value proposition beyond three things, and the site should say so with confidence rather than reach for more:

1. **Power-user control** — the foobar2000 / fooyin lineage: real queue, real playlists, ReplayGain, gapless, format readouts, tag editing, keyboard-first.
2. **Good design and thoughtful UX** — an interface from this decade, made with care.
3. **Customization** — three themes, a token editor, reactive color, a shell you can strip down.

The visitor should leave the homepage thinking: *this is a serious local player that also looks good, and I could make it mine.* The job of the site is to get someone with plenty of other options to download it and give their library a go.

Ownership / anti-streaming is a supporting theme (the "why" section and the fictional library's satire), not the headline. It stays warm, never preachy.

## 2. Voice

**Warm and human. First person singular where an author belongs; second person everywhere else.**

- The author is one person. "I" appears in the hero subhead and the "why" section. Feature copy talks to *you* about *your* library and does not use "I" or "we".
- Confident, not defensive. No caveats about macOS beyond "Windows and Linux", no bit-perfect disclaimers, no "we're new so be gentle", no license talk. Network features being opt-in gets one line in the feature grid, nothing more.
- Modest in scale, proud in craft. It is fine to say "a music player" and let the screenshots and specifics carry the weight.
- Concrete over clever. Name the thing: FLAC, ReplayGain, 100k tracks, Ctrl+K, .m3u8. Specific nouns are what make copy feel human rather than generated.
- American spelling: color, customization, favorite, catalog, organize. (The app has British strings — *colour*, *customisation* — that need a follow-up pass in the app repo. The site does not wait for it.)
- Wordmark stays lowercase `oscine` next to the mark; prose uses "Oscine".

### Tells to avoid

These are what make the current copy read as machine-written. Do not use them.

- Fragment stacks for punch: ~~"No account. No disappearing catalogue. No cut of a listen."~~
- "Not X, but Y" / "X, not Y" framings: ~~"Named recipes, not a model."~~ ~~"A library, not a feed."~~
- Triads for rhythm's sake, and em-dash chains that swerve mid-sentence.
- "It's not just a…", "whether you're… or…", "seamless", "effortless", "elevate", "supercharge", "at the end of the day".
- Jokes at a competitor's expense (~~"chrome from 2004"~~, ~~"a folder and a prayer"~~), and self-deprecating hedges (~~"the honest version of we just shipped this"~~).
- Rhetorical questions as headers.
- Over-explaining a mechanism in marketing copy. Save the *how* for Learn.

### Reference sentences

Hero and subhead (agreed):

> **Your library, taken seriously.**
> I made Oscine because I wanted a local player with foobar's control, an interface I actually enjoyed looking at, and quicker ways to get at everything I care about in the music I already own.

Feature paragraph, target register:

> **Tunedeck.** A drawer on the right that stays open while you browse. It shows who made the track you're hearing, what the file actually is, what's coming up, and what else in your library is related. Turn on online lookups and it adds a biography and line-ups; leave them off and everything local still works.

"Why" section anchor facts (true, per the author): came from foobar2000 / fooyin and wanted a modern interface; left streaming and rebuilt a local library after playlists rotted; built it around one person's tastes and workflow and a wish for easier access to information about favorite music; sharing it because it might fit someone else's.

### 3.4 Download

- **The site's asset model is wrong.** Real releases (rc.1–rc.3) carry exactly two assets: `Oscine.Setup.<version>.exe` and `Oscine-v<version>-linux.tar.gz`, the tarball bundling the AppImage and the .deb (ci.yml, "release build"). There are no standalone AppImage/.deb assets and no `latest*.yml`/`.blockmap` sidecars. `release.ts` must change to `{ windows, linux }`, with the Linux button offering the tarball and the page explaining it contains both an AppImage and a .deb. Fallback becomes 1.0.0 with those two names.
- **Checksums:** GitHub populates `assets[].digest` (`sha256:…`) on every release asset — verified on rc.3. `release.ts` reads it and the page shows a SHA-256 per download with a copy button. No app-side work.
- "What you need": Windows 10 or later, 64-bit; Linux x86_64 (AppImage needs FUSE 2 or `--appimage-extract-and-run`; .deb for Debian/Ubuntu-family). Two-line "unpack the tarball, then either run the AppImage or `sudo apt install ./oscine_<version>_amd64.deb`".
- "Updates": the app does not use electron-updater (no import in `src/main`, sidecars deliberately excluded), so updates are manual: one sentence pointing at the Changelog page.
- Keep the "macOS is not a target" line to one sentence, no justification.
- **RC tags are not marked pre-release** (`gh release create` without `--prerelease`), so `/releases/latest` returns rc.3 today. Either pass `--prerelease` for `-rc.` versions in ci.yml (recommended; one-line change in the app repo) or accept that the site shows RCs as latest until 1.0.0 ships.

### 3.5 Changelog

- `src/data/releases.ts`: fetch `GET /repos/thoughtreactordm/oscine/releases` (paginated) at build time. The repo is public, so `GITHUB_TOKEN` is optional; set it on Vercel anyway (unauthenticated builds share Vercel's egress IPs and can hit the 60/hr limit). If the fetch fails, fail the build rather than shipping an empty page.
- Render each release body as markdown (`marked`, sanitized). Pre-releases shown with a badge; drafts skipped.
- **Release bodies today are GitHub's auto-generated "What's Changed" PR lists** with `@mdelally` mentions and compare links. Rendered raw they read like a CI log. Two options: (a) write the 1.0.0 release notes by hand on GitHub in the site's voice and accept the older entries as-is (they're pre-1.0 history), or (b) post-process: strip the "Full Changelog" line and the `by @user in <url>` suffixes, keep the PR titles as bullets. Do (b) regardless; do (a) for 1.0.0.
- Page header links to Download. Each entry links to its GitHub release for assets.

## 5. Capture pipeline

Everything lives in this repo under `tools/capture/` so the shots are reproducible after a UI change.

### 5.1 `make-library.mjs` — a fictional, playable library

**Status: built.** `tools/capture/library.json` (17 artists, 43 albums, 373 tracks, 2 podcasts) + `make-library.mjs` + `serve.mjs`. `node tools/capture/make-library.mjs` writes ~700 MB to `~/oscine-capture` in under a minute (`--only "Artist"`, `--force`, `--dry-run`, `--out DIR`). Verified: stereo, 44.1k/16 and 48k/24 FLAC, MP3 with APIC, Opus/Ogg with Vorbis comments, disc and compilation tags, ReplayGain on 16 FLAC albums, feeds with enclosures. Covers: every album and both podcasts are 1000×1000 crops derived from `covers/sources.json` (photographic Unsplash License images — landscapes, architecture, textures; no 3D/gradient abstracts). Raw downloads cache in gitignored `covers/sources/`. A generated gradient remains the last-resort fallback if a download fails.

`scripts/seed-synthetic-library.mjs` in the app only inserts DB rows (no files, no art, nothing plays), so it is useless for screenshots. Generate real files instead:

- ~15 artists, ~40 albums, 6–12 tracks each, in the site's existing satirical register (streaming-trope ribbing: *Residual Royalty — Owned Until Revoked*, *Pennyweight — Premium Silence*, *The Region Locks — A Catalogue of Absences*). Keep names invented and non-trademark; no lookalike bands or services. Author the list in `tools/capture/library.json` so it can be reviewed.
- Audio: `ffmpeg` synthesizes 20–40 s of gently varying tone/noise per track (short so the listened-threshold trips fast and playing the whole library takes minutes), except the designated 100 s capture lead needed for the agreed ~1:10 playhead. Mix of FLAC (most), MP3, Opus, Ogg Vorbis — real files in each codec so the format readout is honest. 44.1k/16-bit, a couple of albums at 48k/24-bit for variety.
- Tags: artist, album, album artist, title, track/disc numbers, genre, year (1968–2025), embedded cover. Roughly half the albums carry ReplayGain tags (`metaflac --add-replay-gain` for FLAC); the rest are left for the app to measure so that path is exercised.
- Covers: photographic Unsplash images, downloaded to `tools/capture/covers/sources/` and listed in `sources.json` with photographer and URL. If a cover cannot be sourced, fall back to a generated abstract (gradient + grain) rather than blocking.
- Output: `~/oscine-capture/library/Artist/Album/NN Title.ext`. A local RSS feed for one or two fictional podcasts is served from `~/oscine-capture/podcasts/` via a tiny static server so the Podcasts view has real subscriptions without showing anyone's actual show.

### 5.2 `shoot.mjs` — drive the app and capture

- Throwaway profile: `XDG_CONFIG_HOME=~/oscine-capture/config` so nothing touches the real install. First launch with the profile empty to capture `onboarding`; then either complete the wizard or set `interface.onboardingCompleted = true` in the settings table.
- Launch: `npm run dev -- -- --remote-debugging-port=9222` in the app repo. Attach with a CDP client (`chrome-remote-interface` or raw WebSocket, same as the app's `scripts/cdp-eval.mjs`).
- Set state via CDP `Runtime.evaluate` against the renderer stores (theme, view, Tunedeck tab, palette open). Build history by playing tracks and skipping at the threshold, or by inserting rows into the listens table if the schema is simple enough — check `src/main` first.
- Capture with `Emulation.setDeviceMetricsOverride({deviceScaleFactor: 2})` + `Page.captureScreenshot`. Write to `src/assets/screenshots/<key>.png`.
- Re-runnable: the script takes a shot key or `--all`.

### 5.3 Risks in capture

- **Artist biography pane needs a real artist.** Fictional artists get nothing from MusicBrainz. Decision: shoot the Tunedeck Artist tab in its offline state (in-library data only). If a biography shot is wanted for Learn, capture one against a real artist from a real library and crop tightly enough that no cover art is identifiable.
- **Discover recipes need history.** Confirm which of the nine recipes fire with a small library; adjust the library size or history seeding until at least four shelves show.
- **Window size is hard-coded.** If 1280×820 is too tight for a section, resize via `Browser.setWindowBounds` rather than patching the app.

### 6.1 Bug: unstyled flash on page load (live in production; not a dev artifact)

**Symptom.** On every cold load the page first paints with no theme colors: the mark is a black disc, the amber eyebrow / "Get Oscine" button / active-nav pill are missing, muted text renders plain white, the mock player loses its chrome. Everything snaps into place when the header's JavaScript finishes. Measured against `www.oscine.app` with a headless Chromium CDP probe, cache disabled: the wrong state is visible from first paint (~240 ms) until ~480 ms on a fast connection, and from ~330 ms until ~3.2 s throttled to 1.5 Mbps. The fonts swap in separately (system → Roboto/Sora) a few hundred ms after `load`. There is no hydration mismatch (Vue's dev build logs none) and CLS is negligible (0.001) — this is a paint/color flash, not a layout one, which is why it reads as "CSS jank".

**Root cause 1 — Nuxt UI's color tokens are generated at runtime.** `@nuxt/ui/dist/runtime/plugins/colors.js` builds the `--ui-color-primary-*`, `--ui-color-neutral-*`, `--ui-primary`, … variables from `ui.colors` and injects them as `<style id="nuxt-ui-colors">` through `useHead`. Under Nuxt that is server-rendered into `<head>`; under Astro's Vue renderer there is no head manager, so the block only appears after the `SiteHeader` island hydrates (`client:load` → dynamic `import()` after `astro:load`, ~460 KB of JS). The built stylesheet references `var(--ui-color-neutral-900)` etc. but never defines them, and `dist/index.html` contains zero `--ui-color-*` declarations. Until hydration every `bg-primary`, `text-muted`, `bg-elevated`, `border-default` resolves to nothing.

**Root cause 2 — `Mark.vue`'s scoped style ships in JS.** `.oscine-mark__disc { fill: var(--ui-primary) }` is not in `download.*.css`; it is injected from `SiteHeader.*.js`. Even with the tokens fixed the disc would be black until hydration.

**Root cause 3 (minor) — font swap.** Fontsource faces are `font-display: swap` and nothing is preloaded, so `document.fonts.status` is still `loading` at the `load` event; text reflows when Sora/Roboto arrive.

**Status: fixed** (`src/styles/ui-colors.css`, mark fills moved to `global.css`, font preloads in `BaseLayout.astro`). Verified with the probe against `astro preview`: at `DOMContentLoaded`, before the island hydrates and with no runtime `#nuxt-ui-colors` style present, `--ui-primary` already resolves to amber, the mark's computed `fill` and the CTA's `background-color` are amber, and `document.fonts.status` is `loaded`. Production before the fix, same instant: empty, `rgb(0,0,0)`, transparent, `loading`.

**Fix as applied.**
1. Define the tokens statically. Add `src/styles/ui-colors.css` with the block in Appendix A (it is exactly what the plugin generates for `primary: amber, neutral: taupe`) and `@import` it from `global.css` after `@nuxt/ui`. The site never changes colors at runtime, so static is correct; if `ui.colors` in `astro.config.ts` ever changes, regenerate the block. The runtime plugin will still inject its copy on hydration — identical values, harmless.
2. Drop the scoped style from `Mark.vue` and put the two fill rules in `global.css` (unscoped, so they land in the CSS bundle). `fill-inverted` is not a Tailwind utility here — `text-inverted` is a bespoke Nuxt UI utility, not a theme color — so plain CSS is the honest option.
3. Preload the two latin woff2 files: `import soraUrl from '@fontsource-variable/sora/files/sora-latin-wght-normal.woff2?url'` (same for Roboto) in `BaseLayout.astro` and emit `<link rel="preload" as="font" type="font/woff2" crossorigin href={soraUrl}>`. Optionally trim the Roboto subsets to latin + latin-ext (the CSS currently declares cyrillic, greek, vietnamese, math, symbols).
4. Verify with the probe: first screenshot after first paint must already show amber; `document.fonts.status === 'loaded'` by `load`. Probe script: `/tmp/flash-probe/probe.mjs` (CDP, no dependencies; `node probe.mjs <url> <outdir> [slow]`) — worth moving under `tools/` if we keep measuring.
